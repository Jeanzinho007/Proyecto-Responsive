STAKEHOLDERS

¿Que es un stakeholders?

Un stakeholder es cualquier persona, grupo u organización que tiene algún interés (económico, laboral, social o, incluso, ambiental) en una organización, proyecto o decisión corporativa. Este vínculo puede darse por una participación directa en las actividades de la empresa; o bien, por el impacto que sus decisiones puedan tener sobre terceros o en el entorno, ya sea positivo o negativo.

Clasificación

Stakeholders internos

Son aquellos que forman parte activa de la compañía y participan en su funcionamiento diario. Entre los ejemplos más comunes, se encuentran:

  • Trabajadores o empleados
  • Directivos
  • Accionistas
  • Propietarios o fundadores

Stakeholders externos

Aunque no forman parte de la organización, pueden verse afectados

por sus decisiones. Algunos ejemplos son:

  • Clientes o consumidores
  • Proveedores y distribuidores
  • Comunidad local o sociedad en general
  • Gobierno y organismos reguladores
  • Competencia

Que es un requerimiento funcional

Los requisitos funcionales son pautas específicas que describen los comportamientos, funciones y operaciones que debe realizar un software o sistema.

En el desarrollo de software y sistemas, estos requisitos describen lo que debe hacer el sistema para satisfacer las necesidades de los usuarios y los objetivos comerciales. Los requisitos funcionales suelen detallarse en la documentación, como una especificación de requisitos, para garantizar la claridad y la alineación entre los equipos de desarrollo, las partes interesadas y los usuarios finales.

Ejemplo:

  • Inicio de sesión de usuario:El sistema debe permitir a los usuarios iniciar sesión utilizando un nombre de usuario y contraseña válidos.
  • Procesamiento de Negocios:El sistema debe procesar los pagos con tarjeta de crédito y proporcionar a los usuarios un recibo cuando las transacciones sean exitosas.
  • Recuperación de datos:El sistema debe recuperar y mostrar datos específicos del usuario de la base de datos en función de las consultas de búsqueda.

Que es un requerimiento no funcional

Los requisitos no funcionales especifican criterios que evalúan cómo un sistema realiza una función, en lugar de la función en sí. Mientras que los requisitos funcionales describen funciones específicas del sistema, los requisitos no funcionales definen aspectos como el rendimiento, la seguridad, la usabilidad, la fiabilidad y la escalabilidad.

Ejemplo:

  • El sistema debe restablecer la contraseña en 3 segundos.

REQUERIMIENTOS NO FUNCIONALES

Requerimientos no funcionales Qué Es Ejemplo
Rendimiento Define cómo de rápido, eficiente y estable opera un sistema al ejecutar sus tareas, enfocándose en la velocidad de respuesta, el uso de recursos y la capacidad de carga bajo condiciones específicas. Una página web debe cargar completamente en menos de 3 segundos.
Seguridad Define cómo el sistema protege sus datos, recursos y usuarios contra accesos no autorizados, ataques maliciosos o pérdidas accidentales de información. Las contraseñas en la base de datos deben guardarse cifradas mediante el algoritmo AES-256.
Usabilidad Define cómo de fácil, intuitivo y satisfactorio resulta para el usuario interactuar con el sistema. Un usuario nuevo debe ser capaz de completar el registro en menos de 2 minutos sin ayuda externa.
Accesibilidad Define cómo el sistema garantiza que cualquier persona pueda percibir, entender, navegar e interactuar con el software, sin importar sus capacidades físicas, sensoriales o cognitivas. Todos los elementos visuales interactivos deben mantener un contraste de color mínimo de 4.5:1 respecto al fondo.
Disponibilidad Define el porcentaje de tiempo que el sistema debe estar operativo y listo para ser usado por los usuarios. El sistema debe tener una disponibilidad del 99.9% de forma anual (permitiendo máximo 8.76 horas de caída al año).
Escalabilidad Define la capacidad del sistema para manejar un crecimiento en el volumen de trabajo (más usuarios, más datos o más transacciones) sin perder rendimiento La base de datos debe ser capaz de soportar un incremento del 300% en el volumen de registros mensuales sin degradar el tiempo de respuesta.
Portabilidad Define la facilidad con la que el software se puede trasladar de un entorno de hardware o software a otro. La aplicación móvil debe poder ejecutarse tanto en Android 11 o superior como en iOS 15 o superior compartiendo el 80% del código base.
Mantenible Define el esfuerzo requerido para modificar el sistema, ya sea para corregir errores, mejorar componentes o adaptarlo a nuevos cambios. El código fuente debe estar estructurado bajo la arquitectura de microservicios y poseer una cobertura mínima del 80% en pruebas unitarias.
Compatibilidad Define la capacidad del sistema para convivir, intercambiar información o ejecutar tareas en conjunto con otros sistemas o componentes en el mismo entorno. El sistema debe ser totalmente compatible con las API de pago de Stripe y PayPal para procesar transacciones externas.
Confiabilidad Define la capacidad del sistema para realizar sus funciones requeridas sin fallas durante un período de tiempo específico y bajo condiciones determinadas. El sistema debe garantizar que el 99.99% de los cálculos de nómina mensuales se procesen de forma exacta y sin errores de redondeo.
Restricciones Tecnológicas No son atributos de calidad, sino limitaciones, decisiones de diseño obligatorias o marcos de trabajo impuestos que el equipo de desarrollo debe cumplir estrictamente. El sistema web debe ser desarrollado utilizando Node.js en el backend y PostgreSQL como motor de base de datos relacional.
